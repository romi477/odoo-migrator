# odoo-migrator — FAQ

Простым языком о том, как работает приложение. Единственный документ
проекта на русском; остальная документация — на английском, см.
[docs/README.md](README.md).

---

## Что это вообще такое

**Что делает odoo-migrator?**

Проводит кастомный проект аддонов Odoo через смену версии фреймворка —
17→18 или более длинный прыжок — модуль за модулем, против двух живых
контейнеров. Человек подключается на чекпоинте пачки, а не сидит над
каждым файлом.

**Зачем, если можно переписать модули руками?**

Один модуль — можно. На проекте из десятков и сотен повторяется один и
тот же класс поломок, старая версия должна оставаться доступной, чтобы
ответить «а как это вообще работало?», а упавший апгрейд на модуле 40 не
должен заставлять заново выводить правила, которые уже дал модуль 3.

Инструмент держит старый контейнер только на чтение, пишет новое дерево
через ограниченный File API, ставит апгрейд на новый контейнер, гоняет
тесты и останавливается на чекпоинте с диффами.

**Кто им пользуется?**

Ты, через браузер, на своей машине. n8n — исполнитель одного модуля, не
второй продукт и без памяти о проекте. Модель внутри n8n ходит в тот же
File API и тот же прокси Sheller, которые можно дернуть curl'ом —
отдельного урезанного интерфейса для агента нет.

## Как это устроено

**Что из чего состоит?**

Четыре части:

1. **Приложение** — FastAPI + SQLite на твоей машине. Очередь, пачки,
   правила, заметки, находки. Источник истины.
2. **Веб-страница** — Jinja, htmx, Alpine, один SSE-поток. К приложению
   ходит без ключа.
3. **n8n** — контейнер, прибитый к 2.39.9, либо in-process заглушка с
   тем же контрактом вебхука. Чистый исполнитель.
4. **odoo-sheller** — демон на `127.0.0.1:8765`, который держит открытым
   `odoo-bin shell` внутри каждого контейнера Odoo.

С обоими разговаривает только приложение. n8n адрес 8765 не видит.

**Мы переписываем апгрейд Odoo?**

Нет. Новый контейнер сам ставит и апгрейдит модуль, который записала
переписка. Тесты — тесты Odoo. Sheller — живая консоль, не второй ORM.

**Где физически происходит переписка?**

На диске, в пути нового проекта, через
`PUT /api/migrations/.../files`. n8n твоё дерево не монтирует. Путь, который
выходит за два настроенных корня, — 403.

## Миграции, пачки, джобы

**Открытие второй миграции останавливает первую?**

Нет. Переключатель меняет только экран. Счётчик в шапке — сколько сейчас
в полёте.

**Что такое пачка (batch)?**

Группа модулей, которую ты собрал на Tree (Group или перетаскивание на
другую ноду) и запустил кнопкой **Batch**. Идут **последовательно**, в
порядке зависимостей. После группы — чекпоинт; стартовать другую пачку,
пока эта сидит на ревью, нельзя.

**Что такое джоб?**

Один модуль, один прогон картриджа. Attempt — это ретрай внутри этого
прогона. Цикл на канвасе ограничен `retry_limit`, а не Max Iterations у
агентской ноды.

**Почему нельзя Batch до smoke-run?**

Когда картридж уже установлен, непроверенный пин не должен гнать две
сотни модулей. Smoke-run гоняет самый маленький модуль; вердикт — это
колбэк, а не мгновение после триггера. Если не установлено ничего,
приложение сидит на своей заглушке и пачка разрешена — так сюит живёт
без n8n.

**Модуль прошёл, а дифф на чекпоинте пустой.**

Картридж прислал `attempts: []`, и на новой стороне не было записи, в
пути которой имя модуля было папкой. Стоковый `Mark passed` пишет
attempt; записи File API заполняют пустой `diff`. Записи в старый
проект — не дифф этого джоба.

**Skip и Archive — это одно?**

Нет. Skip (кнопка на дереве; в строке это всё ещё `struck_out`) прячет
модули от Migrate/Batch и сам себя отменяет. Archive убирает всю
миграцию с Overview. Открытие другой миграции первую не архивирует.

## n8n

**Обязательно поднимать n8n?**

Нет. Пустой `n8n_base_url` — in-process заглушка. UI, последовательная
пачка, чекпоинт, File API и тесты работают. Чего не будет — настоящей
переписки: заглушка говорит контрактом, код она не портит.

**Почему именно 2.39.9?**

Об эту версию закрыли контракт вебхука. Плавающий `latest` на спайке
как раз и оказался 2.39.9; прибить картридж и не прибить образ нельзя
одновременно. Подробности: [n8n.md](n8n.md) (по-английски).

**Ответил на Tree, а джоб всё ещё `waiting_for_human`.**

Выход ноды Wait — это тело resume-запроса (`$json.body.answer`), а не
джоб. Если канвас не собирает item заново из **Before wait**, всему
остальному циклу нечего есть. Стоковый так и делает; руками
поправленный картридж — нет.

**Почему `app_base_url` — не `http://127.0.0.1:8000`?**

n8n в контейнере. Этот адрес — сам контейнер. Приложение отказывается
класть loopback в триггер, чтобы падение было здесь, а не через два
часа пачки на Linux. Нужен адрес, куда контейнер реально ходит
(`host.docker.internal` или LAN-IP хоста, если расширили `--host`).

## Правила и находки

**Почему один файл на версию, а не на пару?**

Парные документы растут как квадрат числа версий, а прыжок 16→19 не
нашёл бы что читать. `rules/18.0.md` — «как приземляться на 18.0».
Приложение склеивает исходную и каждую следующую до целевой.

**Куда деваются findings?**

Копятся внутри одного джоба и приезжают колбэком. На чекпоинте
**Promote** дописывает находку в файл версии, который ты выбираешь.
Следующий модуль уже видит этот текст в промпте. Правка rules в середине
пачки меняет следующий модуль; хеш на джобе помнит, что видел этот.

**`sync` и `batch_defer`?**

`sync`: канвас ждёт. Ответ на Tree всегда покупает ещё одну переписку.
`batch_defer`: агент записывает допущение и идёт дальше; список читаешь
на чекпоинте.

## Sheller и контейнеры

**Приложение само создаёт контейнеры Odoo с нуля?**

Нет. Миграция указывает на два уже существующих compose-проекта.
**Up** поднимает наши; **Attach** цепляется к уже запущенным; чужой порт
— ошибка. Демон Sheller либо уже сидит на 8765, либо его спавнят; чужой
демон на этом порту не останавливают.

**Почему n8n не ходит в Sheller напрямую?**

Демон слушает только loopback. Этот адрес — вся граница вокруг
`SUPERUSER_ID` без аутентификации. Внутри контейнера n8n `127.0.0.1` —
это n8n. Приложение проксирует белый список (сессии, контейнеры, probe).
Журналы и admin — отказ.

**Он закоммитит в старую базу?**

Нет. Commit разрешён на новом контейнере и запрещён на старом. Старая
сессия держится весь прогон, чтобы на третьей попытке всё ещё можно
было спросить «а как это работало?».

## Безопасность, коротко

У страниц нет логина. Граница — loopback; `--host 0.0.0.0` открывает все
интерфейсы, потому что Docker Desktop не оставляет более узкого адреса,
куда контейнер сможет достучаться. File API и прокси требуют ключ в
`~/.odoo-migrator/api.key` — процесс печатает путь, никогда значение.

Зачем каждая из этих границ: [security.md](security.md) (по-английски).

## Чего ещё нет

Цикл MVP есть: триггер, переписка, апгрейд, тесты, чекпоинт, promote,
ретрай. Чего нет в обещании: что реальный клиентский проект выйдет с
той стороны без чтения диффов. Качество здесь — это качество промпта и
правил.

Намеренно не в этом круге: Tauri, канвас n8n внутри приложения,
LiteLLM, свой `n8n-nodes-sheller`, `docker login` из приложения,
редактор rules в UI, Windows. У каждого есть записанная причина в спеке
или в плане.

**Что поставить?**

Python 3.12, [uv](https://docs.astral.sh/uv/) (или pip + venv), Docker,
два compose-проекта Odoo и odoo-sheller (или пусть приложение его
поднимет). n8n нужен, когда понадобится настоящий картридж. Сюиту не
нужно ничего из этого, кроме `@pytest.mark.live`.
