# odoo-migrator — FAQ

Простым языком о том, как работает приложение. Единственный документ
проекта на русском; остальная документация — на английском, см.
[docs/README.md](README.md).

---

## Что это вообще такое

**Что делает odoo-migrator?**

Проводит кастомный проект аддонов Odoo через смену версии фреймворка —
17→18 или более длинный прыжок — модуль за модулем, против двух живых
контейнеров. Человек подключается на чекпоинте пачки, а не сидит над
каждым файлом.

**Зачем, если можно переписать модули руками?**

Один модуль — можно. На проекте из десятков и сотен повторяется один и
тот же класс поломок, старая версия должна оставаться доступной, чтобы
ответить «а как это вообще работало?», а упавший апгрейд на модуле 40 не
должен заставлять заново выводить правила, которые уже дал модуль 3.

Инструмент держит старый контейнер только на чтение, пишет новое дерево
инструментами каталога, ставит апгрейд на новый контейнер, гоняет тесты
и останавливается на чекпоинте с диффами.

**Кто им пользуется?**

Ты, через браузер, на своей машине. Раннер — часть этого процесса.
Провайдер делает один ход одной модели и ничего о проекте не помнит.

## Как это устроено

**Что из чего состоит?**

Три части:

1. **Приложение** — FastAPI + SQLite на твоей машине. Очередь, пачки,
   правила, заметки, находки, картридж. Источник истины. Раннер — поток
   внутри него. Без `ODOO_MIGRATOR_RUNNER=native` в `~/.odoo-migrator/.env`
   (или в окружении процесса) это заглушка. Файл читается один раз при старте.
2. **Веб-страница** — Jinja, htmx, Alpine, один SSE-поток. К приложению
   ходит без ключа.
3. **odoo-sheller** — демон на `127.0.0.1:8765`, который держит открытым
   `odoo-bin shell` внутри каждого контейнера Odoo.

Клиент Sheller — только приложение.

**Мы переписываем апгрейд Odoo?**

Нет. Новый контейнер сам ставит и апгрейдит модуль, который записала
переписка. Тесты — тесты Odoo. Sheller — живая консоль, не второй ORM.

**Где физически происходит переписка?**

На диске, в пути нового проекта, через `write_file`. Путь, который
выходит за настроенный корень, отвергается.

## Миграции, пачки, джобы

**Открытие второй миграции останавливает первую?**

Нет. Переключатель меняет только экран. Счётчик в шапке — сколько сейчас
в полёте.

**Что такое пачка (batch)?**

Группа модулей, которую ты собрал на Tree (Group или перетаскивание на
другую ноду) и запустил кнопкой **Batch**. Идут **последовательно**, в
порядке зависимостей. После группы — чекпоинт; стартовать другую пачку,
пока эта сидит на ревью, нельзя.

**Что такое джоб?**

Один модуль, один прогон картриджа. Attempt — круг по ветке провала,
ограниченный `retry_limit`, а не числом вызовов внутри одного хода модели.

**Почему нельзя Batch до smoke-run?**

Когда картридж уже установлен, непроверенный пин не должен гнать две
сотни модулей. Smoke-run гоняет первый невычеркнутый модуль по имени;
вердикт — результат джоба, а не мгновение старта. Если не установлено
ничего,
приложение сидит на своей заглушке и пачка разрешена — так сюит живёт
без модели и без контейнеров.

**Модуль прошёл, а дифф на чекпоинте пустой.**

Ни один шаг, которому разрешён `write_file`, не изменил файл внутри
модуля. Записи в старый проект — не дифф этого джоба.

**Exclude и Archive — это одно?**

Нет. **Exclude** на Tree (`struck_out`) убирает модули из Migrate/Batch
по графу depends: волна или multi-select тянет downstream;
**Include** идёт вверх по depends. Archive убирает всю миграцию с
Overview. Открытие другой миграции первую не архивирует.

## Раннер

**Нужен ли ключ модели, чтобы открыть UI?**

Нет. По умолчанию исполнитель — заглушка. Страницы, очередь, чекпоинт и
тесты работают. Настоящего порта не будет, пока не заданы
`ODOO_MIGRATOR_RUNNER=native` и ключ провайдера.

**Ответил, а джоб стал `unknown`, а не running.**

Поток, который ждал, уже нет — обычно после рестарта. Ответ сохранён и
лежит в нити чекпоинта. Джоб не делает вид, что ещё идёт.

**Какие модели можно назвать в картридже?**

Те, которые принимает зарегистрированный провайдер. Anthropic:
`claude-opus-5` и `claude-sonnet-5`. Cursor: имена из списка плюс
`auto-smart` с параметрами. OpenCode описан и не построен.

## Правила и находки

**Почему один файл на версию, а не на пару?**

Парные документы растут как квадрат числа версий, а прыжок 16→19 не
нашёл бы что читать. `rules/18.0.md` — «как приземляться на 18.0».
Приложение склеивает исходную и каждую следующую до целевой.
`rules/common.md` уходит один раз перед этим стеком.

**Куда деваются findings?**

Копятся внутри одного джоба и остаются на нём. На чекпоинте
**Promote** дописывает находку в файл версии, который ты выбираешь.
Следующий модуль уже видит этот текст в промпте. Правка rules в середине
пачки меняет следующий модуль; хеш на джобе помнит, что видел этот.
В чекауте дописывается файл из git. Установленная сборка ничего внутри
себя не хранит, поэтому Promote пишет в `~/.odoo-migrator/rules/`, и эта
копия читается первой.

**`sync` и `batch_defer`?**

`sync`: джоб стоит, пока ты не ответишь. `batch_defer`: шаг записывает
допущение и идёт дальше; список читаешь на чекпоинте.

## Sheller и контейнеры

**Приложение само создаёт контейнеры Odoo с нуля?**

Нет. Миграция указывает на два уже существующих compose-проекта.
**Up** поднимает наши; **Attach** цепляется к уже запущенным; чужой порт
— ошибка. Демон Sheller либо уже сидит на 8765, либо его спавнят; чужой
демон на этом порту не останавливают.

**Он закоммитит в старую базу?**

Нет. Commit разрешён на новом контейнере и запрещён на старом. Старая
сессия живёт весь прогон, кроме паузы на человека: тогда закрываются
обе, и открываются снова, если тот же поток получил ответ.

## Безопасность, коротко

У страниц нет логина. Приложение слушает только `127.0.0.1`. Ключи
провайдеров хранятся и обратно не показываются. Admin-ключ Sheller не
читается.

Зачем каждая из этих границ: [security.md](security.md) (по-английски).

## Чего ещё нет

Цикл есть: порт, апгрейд, тесты, чекпоинт, promote, ретрай. Чего нет в
обещании: что реальный клиентский проект выйдет с той стороны без
чтения диффов. Нативный раннер включается отдельно, пока один настоящий
модуль не проверен руками. Качество здесь — это качество промпта и
правил.

Намеренно не в этом круге: Tauri, LiteLLM, `docker login` из приложения,
редактор rules в UI, Windows. OpenCode описан и не построен.

**Что поставить?**

Python 3.12, [uv](https://docs.astral.sh/uv/) (или pip + venv), Docker,
два compose-проекта Odoo и odoo-sheller (или пусть приложение его
поднимет). Ключ провайдера — только при `ODOO_MIGRATOR_RUNNER=native`.
Сюиту не нужно ничего из этого, кроме `@pytest.mark.live`.
