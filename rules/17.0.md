# 17.0

What landing on 17.0 requires. Python 3.10 or newer. Everything in the
16.0 file still applies unless this file replaces it.

## Views

`attrs` and `states` are gone. The parser raises `ValidationError`:
`Since 17.0, the "attrs" and "states" attributes are no longer used.`
Modifiers are Python expressions on the attribute itself:

```xml
<field name="name" invisible="state == 'cancel'" readonly="state != 'draft'"/>
<field name="partner_id" column_invisible="True"/>
```

`invisible`, `readonly`, `required` and, on a list column,
`column_invisible`. `column_invisible` hides the column.
`invisible` hides the cell. The expression sees fields that are
present in the same view, plus `context`, `uid`, `parent`, `id`,
`today` and `now`. A field used in an expression and hidden from the
user stays in the view with `invisible="True"`. Relational fields
arrive as a list of ids.

`states` on a field definition in Python is gone with the view
attribute. Fold that into `readonly` on the view.

The list root tag is still `tree`. The view type is still `tree`.
`view_mode` is still `tree,form`. The schema is still
`tree_view.rng`. The server still aliases `tree` to `list` only for
the web client. `<list>` is not a valid root, and an action
`view_mode` of `list,form` does not open the list. Do not rename
`tree` to `list` for 17.0. An xpath stays `//tree`.

A kanban card is still `t-name="kanban-box"`.

## ORM

- Override `create` with `@api.model_create_multi` and `vals_list`.
  The 16.0 core method already has that signature; an override that
  still takes a single `vals` does not match it.
- `SQL` exists and the ORM uses it internally. A string passed to
  `cr.execute` is still valid.
- `group_operator` is still the aggregation attribute on a field.
  Do not rename it to `aggregator` for 17.0.
- `_sql_constraints` is still the list of `(name, sql, message)`.
- `name_get` is deprecated since 17.0 and the method is still there.
  New code reads `display_name`. Leave an existing override working
  until the target file says the method is gone.
- Access checks are still `check_access_rights` and
  `check_access_rule`. `check_access` is the next version.
- `res.users.groups_id` and `res.groups.users` keep those names.
  `category_id` is still the group category.

## HTTP

A JSON route is `type="json"`. Do not rename it to `jsonrpc` for 17.0.
