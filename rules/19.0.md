# 19.0

What landing on 19.0 adds on top of 18.0. Python 3.10 or newer
(`MIN_PY_VERSION` is `(3, 10)` in this release; 3.12 is 20.0).
Everything in the 17.0 and 18.0 files still applies unless this file
replaces it.

Type annotations are used in core and are not required for a custom
module to load. Do not spend the port adding hints. OWL has not grown
a new major you must rewrite to: if a component fails to start, read
that component's base with `source` on the target container.

## Views

The list root tag stays `list`. `<tree>` is still not a view type,
and `view_mode` stays `list,form`. Same rule as 18.0.

A kanban card must be `t-name="card"`. The 19.0 parser does not fall
back to `kanban-box`. A missing card throws `Missing 'card' template.`

## ORM

- `_sql_constraints` is no longer applied. Defining the attribute
  logs `Model attribute '_sql_constraints' is no longer supported,
  please define models.Constraint on the model.` A constraint is a
  model attribute whose name starts with `_`:

  ```python
  _name_uniq = models.Constraint("UNIQUE(name)", "Name must be unique.")
  _name_idx = models.Index("(name)")
  ```

  `models.UniqueIndex` is the unique-index form. The message may be a
  string, or a function `(env, diag)`.
- `read_group` is deprecated. Backend code calls `_read_group`.
  Formatted output for callers outside the ORM is
  `formatted_read_group`.
- Domains can be built with `odoo.Domain` (`odoo.domain`). A list
  domain still works; use `Domain` when the module composes domains
  in Python.
- `@api.private` marks a method that must not be callable through RPC.
  Put it on helpers that were never meant as public methods.
- `record._cr`, `record._context` and `record._uid` are deprecated.
  Use `record.env.cr`, `record.env.context` and `record.env.uid`.
- `odoo.osv` is deprecated. Import from the module the new source
  uses; confirm with `source` before picking a path.
- Dynamic dates are legal inside domains. That is new capability, not
  a rewrite of existing domains.
- A string `cr.execute` is not banned by the changelog. Prefer `SQL`
  for a query you are already rewriting. Leave a working string if
  the target container accepts it.

## Security groups

On `res.users`, `groups_id` is `group_ids` (assigned directly) and
`all_group_ids` (including implied groups). On `res.groups`, `users`
is `user_ids` and `all_user_ids`. Do not pass `groups_id` to
`create`.

`res.groups.category_id` is replaced by `privilege_id` pointing at
`res.groups.privilege`. Read `res.groups` on the target container with
`source` before rewriting a security file: only change a group that
actually sets `category_id`.

## HTTP

A JSON controller route is `type="jsonrpc"`. The method is called the
same way. `type="json"` still runs: since 19.0 it is a deprecated
alias, warns, and is rewritten to `jsonrpc`. Write `jsonrpc`.
