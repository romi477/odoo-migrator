# 18.0

What landing on 18.0 adds on top of 17.0. Python 3.10 or newer.
Everything in the 17.0 file still applies unless this file replaces it.

## Views

The list root tag is `list`. `<tree>` is not a valid root and `tree`
is not a view type.

`ir.ui.view.type` selects `list`, not `tree`. The schema is
`list_view.rng` and its element is `list` only. There is no alias
that rewrites a `<tree>` arch into `<list>`. An action `view_mode`
defaults to `list,form`; a mode that still says `tree` does not open
the list. Core views in `base` are `<list>`.

Rename the root, the `view_mode` string, and every xpath that says
`tree` when the parent on the target container is a list:

```xml
<list string="Things">
    <field name="name"/>
</list>
```

```xml
<field name="view_mode">list,form</field>
```

```xml
<xpath expr="//list/field[@name='name']" position="after">
    <field name="code"/>
</xpath>
```

An xpath of `//tree` does not match a parent whose root is `list`.
Match the root the parent view actually has. Do not rename a `tree`
that is not a list view (a search group, a field name, a comment).

View modifiers stay the 17.0 Python expressions, including
`column_invisible`.

A kanban card template is `t-name="card"`. `t-name="kanban-box"`
still loads: the client warns `'kanban-box' is deprecated, define a
'card' template instead` and falls back to it. Write `card`. If
neither template is present the client throws `Missing 'card'
template.`

## ORM

- `group_operator` is deprecated. The field setup warns `Since Odoo
  18, 'group_operator' is deprecated, use 'aggregator' instead` and
  copies the value onto `aggregator`. Write `aggregator`.
- `name_get` is gone. The label is `display_name`, computed by
  `_compute_display_name` and searched by `_search_display_name`.
  Do not keep a `name_search` that assumes the old `name_get` path.
- Access is one check: `check_access`, `has_access` and
  `_filtered_access` cover both rights and record rules.
  `check_access_rights` and `check_access_rule` still exist, warn
  `deprecated since 18.0`, and delegate. Write the new names when
  you touch that code.
- Translations are on the environment (`env._`).
- `SQL` is the preferred way to compose a raw query. A string
  `cr.execute` still runs. Rewrite it when you are already editing
  that query, not as a sweep.
- `_sql_constraints` is still the list of tuples. `models.Constraint`
  is not this version's API.
- `read_group` is still the public grouping method.
- Company consistency can be declared instead of hand-written:
  `_check_company_auto = True` on the model and `check_company=True`
  on a `Many2one` that must match `company_id`. Use that where the
  module already checks companies by hand. Do not add it to a model
  that has no company.

## HTTP

A JSON route is still `type="json"`. `jsonrpc` is the next version.

`res.users.groups_id` and `res.groups.category_id` keep those names.
`users` on `res.groups` keeps that name.

## Browser tests

A module's JS tests run on Hoot. QUnit is not this version's runner,
and a QUnit file is not picked up: it is rewritten, not copied.

- A test file is under `static/tests/` and ends in `.test.js`. A file
  without that suffix is a helper the tests import; one ending in
  `.hoot.js` is global to the whole run. Tours stay under
  `static/tests/tours/` and are not unit tests.
- The bundle is `web.assets_unit_tests`, not `web.qunit_suite_tests`:

```python
'assets': {
    'web.assets_unit_tests': [
        'my_module/static/tests/**/*',
    ],
},
```

- A file imports `describe`, `test` and `expect` from `@odoo/hoot`.
  `QUnit.module` becomes `describe` (optional: each file is wrapped in
  one), `QUnit.test(name, async (assert) => ...)` becomes
  `test(name, async () => ...)`, and `assert.strictEqual(a, b)`
  becomes `expect(a).toBe(b)`. A count of elements is
  `expect(selector).toHaveCount(n)`, text is `toHaveText`.
- Server data is mock models, not `serverData`: a class extending
  `models.Model` with `_name`, its fields and `_records`, registered
  with `defineModels`, all from `@web/../tests/web_test_helpers`.
  `makeView` becomes `mountView({type, resModel, arch})`, a mocked RPC
  is `onRpc`, and an interaction is `contains(selector).click()` or
  `.edit(value)`.

Keep what each test asserts. A test that cannot be written for Hoot
is named in the answer with the reason, not dropped in silence.
