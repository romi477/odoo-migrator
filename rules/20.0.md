# 20.0

What landing on 20.0 adds on top of 19.0. PostgreSQL 16 or newer.
Checked against the 20.0 source. Where this file and that source
disagree, call `source` on the target container. Converters under
`odoo/upgrade_code/` are hints. Do not depend on them, and nothing
there rewrites `res.partner`.

Everything in the earlier files still applies unless this file
replaces it. In particular, the 19.0 note that OWL has no new major
stops here.

## Security

`ir.model.access` and `ir.rule` are gone. Both are `ir.access`.
`env['ir.model.access']` and `env['ir.rule']` raise `KeyError`. The
tables `ir_model_access` and `ir_rule` are dropped, so raw SQL on them
fails too. A migration script must guard with
`if 'ir.model.access' in env` before touching the old model. A script
that finds zero rows on an already-migrated database still crashes on
the upgrade where the rows exist.

The file is `security/ir.access.csv`, and the manifest data list uses
that name. Columns:

```text
id,name,model_id,group_id/id,operation,domain
```

`model_id` is the dotted model name, not an xmlid. `operation` is a
string of `c`, `r`, `u`, `d`. Full CRUD is `crud`. Read-only is `r`.

One old `ir.rule` with N groups becomes N rows, each with one
`group_id` and a `domain` (the old `domain_force`). A row **with** a
group is a permission. A row **without** a group is a restriction.
An old global rule (no group) stays a row with no group. An old ACL
whose group was empty is not a restriction: map it to a real group
(`base.group_everyone` is what core's converter uses) and test it.
Do not leave it blank.

CSV cannot carry `noupdate`. A rule that was `<odoo noupdate="1">`
and moved into this CSV loses that flag. Putting the record back in
XML with `noupdate="1"` does not flip an xmlid that already exists.
An upgrade of an installed database needs one post-migrate write of
`noupdate` on that `ir.model.data` row. A fresh install does not.

## res.partner

No converter ships for this. Budget it as its own pass.

- `is_company` is stored computed from `has_vat` and
  `commercial_partner_id`. `create({'is_company': True})` is stored as
  `False` with no error. `write` holds until `vat` changes, then the
  compute resets it. "Company" means this record is its own commercial
  entity **and** it has a tax id. `has_vat` is unchanged: `vat` set and
  not `/`, `na`, or `NA`.
- Do not filter `('is_company', '=', True)` and expect the 19.0 set.
  A match that used to find companies can find none, and an import
  will duplicate them. Keep the external system's answer on the
  module's own mapping model.
- `company_name` is removed. A contact cannot carry a company that is
  not itself a partner.
- `company_type` is removed. It was never for business logic.
- `commercial_company_name` is still stored and searchable. It is now
  `related='commercial_partner_id.name'`. A contact with no parent
  answers with its own name, where 19.0 answered `''`.

## Renames

Apply these where the module uses them. Do not rename globally.

| Was | Now |
|---|---|
| `res.partner.bank.acc_number` | `account_number` |
| `res.partner.bank.sanitized_acc_number` | `sanitized_account_number` |
| `res.partner.bank.acc_holder_name` | `holder_name` |
| `stock.move.product_uom` | `uom_id` |
| `stock.move.line.product_uom_id` | `uom_id` |
| `purchase.order.line.product_uom_id` | `uom_id` |
| `account.payment` state `in_process` | gone; a wizard payment lands in `reconciled`. States are `draft`, `paid`, `reconciled`, `canceled`, `rejected` |

`sale.order.line.product_uom_id` still exists. A global
`product_uom_id` → `uom_id` replace breaks it.

`account.account.code` is no longer one column. It is a per-company
mapping. Raw SQL on `account_account.code` fails.

`ir.actions.report.report_file` is removed. Drop it from report XML.

`ir.attachment.datas` is ignored, with a warning, and the file is
empty. Write `raw`. On `raw`, a `str` is base64 and is decoded;
`bytes` are stored as-is. Passing the base64 text as `bytes` stores
that text. Read `raw.content` for bytes and `raw.to_base64()` for
base64. Any other binary field rejects bare `bytes` (`BinaryValue`,
or a base64 `str` the way RPC sends one).

`res.users.SELF_WRITEABLE_FIELDS` is gone. A field the user may write
on himself is `user_writeable=True` on that field.

`stock.picking._create_backorder` takes
`from_manual_backorder=False` as well as `backorder_moves`. An
override must accept it.

`account.move.payment_state` is unchanged (`not_paid`, `in_payment`,
`paid`, `partial`, `reversed`, `blocked`, `invoicing_legacy`).

`account.report.line` no longer has a boolean `foldable`. The field
is `foldability`, a selection (`foldable`, `always_unfolded`,
`never_unfolded`) computed from the line. Do not set the old boolean
in report XML.

## API

- `ir.config_parameter.get_param` and `set_param` are gone. Read
  with `get_str`, `get_bool`, `get_int`, `get_float`. Write with
  `set_str`, `set_bool`, `set_int`, `set_float`.
- `env.registry.clear_cache()` becomes
  `env.transaction.invalidate_ormcache('default')`.
- `env.clear()` warns and will break. Use `env.transaction.clear()`
  or `env.transaction.reset()`. `clear` drops every environment on
  the transaction, not only this one.
- `odoo.service.db.list_dbs` is `odoo.modules.db.list_dbs`. `force`
  is keyword-only: `list_dbs(force=True)`. `list_dbs(True)` is a
  type error.
- `from odoo.http import db_list` becomes
  `from odoo.http.router import db_list`.
- `from odoo.http import serialize_exception` becomes
  `from odoo.http.dispatcher import serialize_exception`.
- `PG_CONCURRENCY_ERRORS_TO_RETRY` is not exported from
  `odoo.service.model`. The tuple is
  `PG_CONCURRENCY_EXCEPTIONS_TO_RETRY` in `odoo.sql_db`.
- `Registry(db).check_signaling()` becomes `Registry(db)`.
- `record.get_formview_action()` is
  `record.get_record_default_action()`. `_get_access_action` calls
  the new name. A smart button that still calls the old one raises
  `AttributeError`.
- `_read_group(domain, groupby, aggregates)` returns a list of
  tuples, not dicts. `groupby` is a list of field names. Each
  aggregate is `'field:agg'` (`'id:array_agg'`) or `'__count'`.
  The 19.0 form that passed one list of dict-style specs raises.
- An override of `Field._setup_attrs` must be named
  `_setup_attrs__`. The old name is inherited by nothing and raises
  no import error.
- `api.propagate` is removed, and so is the `_returns` marker it
  copied. To keep a wrapper's name and docstring, use
  `functools.update_wrapper`.
- A quantity in a unit uses that UoM: `uom.is_zero(value)`,
  `uom.compare(v1, v2)`, `uom.round(value)`.
  `odoo.tools.float_utils.float_is_zero` still exists. Do not delete
  every call.
- `stock.return.picking` and `product_return_moves` are gone. A
  return is `picking._create_return()`, and the moves are
  `return_picking.move_ids`.
- `Model._table_query` is removed. A SQL-view model needs an `init`
  that matches current core. Read one in the new source before
  writing it.
- A domain `('field', 'in', scalar)` still runs and logs a debug
  warning. Pass a list.
- `_rec_names_search` is a tuple: `('name',)`. A one-element tuple
  needs the comma.
- `copy()` suffixes a `Char` named `name` or `x_name` with
  `(copy)`, unless that field sets `copy` itself. Do not add a
  second suffix.
- `post_init_hook(env)` is unchanged.
- `phone_validation._phone_format()` is unchanged when that module
  is installed. If the name is missing, the module is absent:
  declare it in `depends`. Do not rely on `auto_install`.
- `ir.model.data` fields `name`, `module`, `model`, `res_id`,
  `noupdate` are unchanged.

## QWeb

`t-call` is only valid on a `<t>` element. Values for the called
template are attributes on that tag, not `<t t-set>` children. A bare
attribute is a Python expression. `name.f` is a format string.
`name.translate` is a translated format string. `t-args` is a dict
merged into those values. The tag's body is rendered separately and
passed as slot `0` (`t-out="0"`). A `t-set` left inside the body
updates that slot, not the called template.

In data XML, a file field's `type="base64"` is `type="bytes"`.

## Owl

This is Owl 3, and only in client templates under the module's
static sources. Server QWeb reports stay on `t-esc`. A global
`t-esc` → `t-out` replace breaks those reports.

- `useState({...})` becomes `proxy({...})`.
- `<t t-esc="x"/>` in an Owl template becomes `<t t-out="x"/>`.
- `<t t-slot="default"/>` becomes `<t t-call-slot="default"/>`.
- Component members are `this.menu`, `this.openMenu`, `this.state`.
  Locals from `t-foreach` and `t-set` stay bare.
- `@web/owl2/utils` is a transitional shim for removed lifecycle
  hooks. Do not build new code on it.

## Reports

- `/report/check_wkhtmltopdf` is `/report/get_pdf_engine_state`.
- Product labels: `stock.label_product_product` is
  `product.report_product_template_label_zpl`.
- `print_format` values `2x7xprice`, `4x7xprice`, `4x12xprice`,
  `zplxprice` become `2x7`, `4x7`, `4x12`, `zpl`, plus a boolean
  `with_price`.

## Upgrade mechanics

A migration folder version that is less than or equal to
`ir.module.module.latest_version`, or greater than the manifest
version, never runs. The folder version must sit strictly above
`latest_version` and at or below the manifest.

The registry in a running shell does not see a `.py` edit or a
manifest version bump made after the session opened. Edit, restart
the container, open a new session, then upgrade.

## Signatures

An override copies the method's signature from the new source,
including arguments that are keyword-only. `list_dbs` above is one.
Do not assume a positional argument still binds.

Translation terms are owned by the module. Regenerate that module's
`.pot` rather than expecting a shared pool in `base`. Confirm the
export on the target container before rewriting call sites.
